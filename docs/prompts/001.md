### Confirmed decisions

- One host project `src/DevCommander`, one xUnit project `tst/DevCommander.Tests`, solution `DevCommander.sln`.
- One mission may coordinate several repositories. The mission file is `{DataRoot}/missions/{missionSlug}.md`; `Mission.Id` is an internal GUID and `Mission.Slug` is the unique human identifier.
- Mission files have seven required non-empty sections: Repositories, Goal, In-scope, Out-of-scope, Verification commands, Acceptance criteria, Runtime preference.
- Planner output is `MissionPlan(Tasks)` where each `PlannedTask` has `RepoId`, positive contiguous `Phase`, and non-empty `Description`.
- Same-phase work runs concurrently across repositories. Tasks for one squad run serially; the next global phase waits for all current-phase tasks.
- Attempts are per `TaskItem`, maximum three. Repeated normalized failure twice → `Blocked`; third failure → `RetriesExhausted`.
- All four adapters ship: Claude, Codex, Cursor `agent`, OpenCode. A failed install/auth/headless/sandbox probe marks only that runtime unavailable.
- Strong isolation is mandatory. Every worker is wrapped by `IWorkerSandbox`; worker tools may access only the assigned worktree, a private per-squad runtime home, and minimum worktree-specific git metadata. Everything else is absent. Use runtime-native sandboxing as defense in depth. No unsandboxed fallback.
- Worker environments exclude git-push and deploy credentials. Only host services may push or execute gated commands.
- Cost control is exact where telemetry is authoritative and best-effort otherwise. Reserve a configured maximum estimated charge before every run; do not start if the reservation exceeds the remaining mission budget. Reconcile reported cost afterward. Apply wall-time cancellation to running processes.
- Approval is a transactional, single-use DB state machine. Never use `SuspendsForHost`.
- Telegram slash commands are deterministic DB operations. Free text invokes the supervisor. Do not send `ToolCallReceived` progress to Telegram.
- Notifications are at-least-once and contain a target `ChatId`. State transition, event, and outbox insert are one transaction.
- All singleton/hosted-service boundaries resolve scoped dependencies through `IServiceScopeFactory` or `IDbContextFactory<AppDbContext>`. Use `TimeProvider` for time and retry delays.

## Required technical design

### Mission file grammar

`Repositories` is a markdown bullet list of registered repo IDs.

`Verification commands` contains one `### {repoId}` subsection per repository. Each body is either `repo default` or a bullet list of shell commands.

`Runtime preference` contains `default: {runtime}` and optional `{repoId}: {runtime}` overrides. Selection precedence is repo-specific mission override → mission default → `Repo.DefaultRuntime`.

Require exactly one verification subsection for every listed repository and no unknown subsection. Validate path containment and slug/repo IDs before filesystem access. Snapshot the accepted UTF-8 content and SHA-256 hash into `Mission` before planning. Reject empty tasks, unknown repos/runtimes, repos not listed by the spec, non-positive/non-contiguous phases, or a plan that omits a listed repo.

### Composition root

`Program.cs` must explicitly:

1. Bind and validate options on startup. LLM configuration stores only the environment-variable name for the API key; read the value from the environment and never write it to configuration, DB, or logs. Require an OpenAI-compatible base URL with trailing slash.
2. Register `AppDbContext` with `UseSqlite` using a DB path derived only from `DevCommanderOptions.DataRoot`; use `Default Timeout=30` and pooling.
3. Register `AddDefaultEfCorePersistence<AppDbContext>()`.
4. Register `IPricingSource` as configured host pricing composed with `PricingSources.BuiltIn`; fail startup when a configured NovaCore model has no pricing.
5. Call `AddModelProfiles` for `commander`, `planner`, and `critic` using `OpenAiCompatible.Create`, then register all three keyed factories.
6. Register `TimeProvider.System`, application services, keyed runtime adapters, agent factories, dispatcher, registry, Telegram messenger, and hosted services.
7. Start hosted services in this order: database initializer, runtime capability probe, reconciliation, Telegram polling/inbox processor, notification flusher.
8. Map `/health`.

`DatabaseInitializerHostedService` is an `IHostedService` whose `StartAsync` creates paths, runs migrations, verifies `PRAGMA journal_mode=WAL`, and completes before other hosted services start. Use short transactions, a new context per operation, expected-state/version updates, and bounded `SQLITE_BUSY` retry. Never hold a DB transaction during LLM, process, git, or Telegram I/O.

### Process and sandbox contracts

`IProcessRunner.StartAsync` returns a live `IProcessExecution` with `Pid`, `StartedAt`, `Completion`, and `KillTreeAsync`. Cancellation kills the complete process tree/group and awaits exit. Bound captured output and retain a truncation marker.

`IWorkerSandbox` wraps every CLI with Linux `bubblewrap`:
- prepares a process with cwd = worktree;
- uses `--unshare-all --share-net --die-with-parent --new-session`;
- read-only binds only required system paths (`/usr`, `/bin`, `/lib*`, `/etc`) and CLI binaries;
- read/write binds only the assigned worktree, a private per-squad runtime home, and the worktree-specific git metadata needed for status/diff;
- creates private `/tmp`, `/proc`, and `/dev`, sets `HOME` to the private runtime home, and does not mount the rest of `{DataRoot}`;
- sanitizes environment and removes git-push/deploy credentials;
- probes user-namespace and filesystem isolation at startup;
- refuses execution when isolation cannot be established.

On Linux, use an OS-enforced filesystem sandbox for every adapter; runtime-native controls are additional, not substitutes when they lack OS enforcement. Claude settings must enable sandboxing with `failIfUnavailable=true` and no unsandboxed fallback. Codex uses `--sandbox workspace-write`. Cursor uses `--sandbox enabled`. OpenCode uses a host-owned permission config denying `external_directory`, push/deploy commands, and unapproved external access.

Adapter contract:

```csharp
public interface IRuntimeAdapter
{
    RuntimeKind Kind { get; }
    Task<RuntimeResult> StartAsync(
        RuntimeRunRequest request,
        Func<ProcessStarted, CancellationToken, Task> onStarted,
        CancellationToken ct);
    Task<RuntimeResult> ResumeAsync(
        string sessionId,
        RuntimeRunRequest request,
        Func<ProcessStarted, CancellationToken, Task> onStarted,
        CancellationToken ct);
}
```

`onStarted` persists PID/start time before awaiting completion. `RuntimeResult` contains `SessionId`, `FinalMessage`, `ExitCode`, `CostUsd?`, `Usage?`, and typed `FailureKind` (`TransientNetwork`, `Authentication`, `InvalidInvocation`, `SessionUnavailable`, `Cancelled`, `Other`). Unknown failures are permanent, not network-retryable.

Use `ProcessStartInfo.ArgumentList` and stdin/file input for large prompts where supported; never construct a shell command for CLI adapters. Parse defensively and ignore unknown JSON fields:

- Claude: `claude -p --output-format json`; parse `result`, `session_id`, `total_cost_usd`; resume with `--resume {id}`; pass supported remaining-cost cap.
- Codex: `codex exec --json --sandbox workspace-write`; parse `thread.started.thread_id`, final `agent_message`, and `turn.completed.usage`; resume with `codex exec resume {id}`. Usage-derived cost is estimated unless provider billing is authoritative.
- Cursor: executable defaults to `agent`; `agent -p --output-format json --sandbox enabled --force --trust --workspace {worktree}`; parse `result` and `session_id`; resume with `--resume {id}` only in the unchanged workspace. Use configured estimated reservation because output has no usage/cost.
- OpenCode: `opencode run --format json --auto`; parse `sessionID`, text, and summed `step_finish.part.cost`; resume with `--session {id}`.

Pin tested CLI versions in Docker; executable names remain configurable. Persist native runtime state under `{DataRoot}/runtime-state`; if native resume returns `SessionUnavailable`, fresh-spawn from the ledger exactly once.

### Git and task execution

- Serialize clone, fetch, ref, and worktree-control operations per repository.
- Persist `Repo.DefaultBranch` and `Mission/Squad.BaseCommit`.
- Worktree path: `{DataRoot}/worktrees/{missionId:N}/{repoId}`.
- Branch: `mission/{repoId}/{missionSlug}`.
- Adopt an existing worktree only when gitdir, branch, and mission match; otherwise block safely.
- Workers may edit files but cannot stage, commit, alter shared refs, or push. Bind shared git data read-only and only the current worktree's index metadata read/write. The host alone commits and pushes explicitly as `HEAD:refs/heads/mission/{repoId}/{missionSlug}`, rejecting force/main/master.
- Remove a worktree only after confirmed push and durable repository completion.

Per task:

1. Persist `BaselineCommit` before the first attempt.
2. Atomically reserve attempt number and estimated charge before starting the coder.
3. Build prompt from immutable mission content, repo `AGENTS.md`, current task, prior-phase summaries, and retry evidence.
4. Persist process identity through `onStarted`; user stop is typed cancellation and never becomes a network retry.
5. Compute current-task changes as `BaselineCommit..HEAD` plus uncommitted changes. Empty current-task changes fail even if prior phases changed the branch.
6. Run Critic only on that bounded current-task diff. Validate non-null structured output.
7. Run effective verifier commands sequentially. Before a gated command, create the exact approval transaction and return from the loop, releasing its gate.
8. On failure, increment only this task, record a normalized signature based on sorted blocking findings + command + exit code + normalized failure lines, and apply BR-003.
9. On pass, commit remaining changes if needed and atomically record task `Done`, evidence, and commit SHA. Never rework that task.

Mission coordinator starts all eligible squads for the lowest unfinished global phase. It advances only when all tasks in that phase are done, then passes an aggregate summary to the next phase.

### Approval, state transitions, and recovery

Use the status values and legal progressions in SRS v1.1 §8. Mission aggregation rules are binding: blocked/stopped current-phase squad → mission `Blocked`/`Stopped`; `RetriesExhausted` task → mission and squad `Failed`; budget/deadline → `Halted`; all tasks → `Completed`. Implement transitions as conditional updates (`WHERE Status = expected AND Version = expectedVersion`).

Approval key is `{missionId,squadId,taskId,attempt,commandIndex,commandHash}`. Transaction: create `Pending`, set squad `WaitingApproval`, add event and unique outbox row; then the loop returns. `/approve {approvalId}` conditionally changes `Pending → Approved`, records deciding chat/time, and schedules continuation after commit. Before execution change `Approved → Executing`; after success change `Executing → Consumed`. A recovered `Executing` request becomes `Blocked` and requires explicit human reconciliation.

`/stop` uses `Running → Stopping → Stopped`, cancels and kills the process tree, awaits exit, then commits. A run-generation/version check prevents late completion from overwriting `Stopped`. `/continue` accepts optional guidance and resumes only stopped/blocked tasks with attempts remaining.

Persist checkpoints sufficient to distinguish verified, committed SHA, tasks finalized, and pushed. Reconciliation uses DB + git state to finish interrupted transitions without calling the coder for completed tasks. Verify PID identity with PID + start time before acting. Queue exactly one recovery summary within 60 seconds.

Retry only typed transient worker/git failures with capped exponential backoff + jitter and mission deadline/stop cancellation. Authentication, invocation, sandbox, session (after one fresh fallback), and non-fast-forward failures become `Blocked`. Telegram delivery failures never change squad status.

### Telegram inbox and outbox

Polling first inserts each Telegram update by unique `UpdateId`, then persists the offset. `TelegramInboxProcessorService` claims rows with a lease and processes each chat in `UpdateId` order. Deterministic command effects are idempotent:

- `/missions`
- `/start {missionSlug}`
- `/status {missionSlug}`
- `/approve {approvalId}`
- `/stop {missionSlug} {repoId}`
- `/continue {missionSlug} {repoId} [guidance]`
- `/whoami`

Unknown chats are ignored except `/whoami`. Free text opens `telegram-{chatId}` through the keyed commander factory, sets `ExecutionPrincipal.ActorId`, and invokes the same services through commander capabilities.

Register `RegisterRepository : Capability<RegisterRepositoryArgs, RegisterRepositoryResult>` as an `ICommanderCapability`. Its input is `{ repoId, source, defaultBranch, defaultRuntime, verifyCommands[], gatedOps[] }`; validate all values and persist atomically. `GatedOps` are case-insensitive substring patterns matched against the full verifier command after trimming and collapsing whitespace.

Outbox rows include `ChatId`, unique `LogicalKey`, attempts, lease/next-attempt data, and last error. Insert them in the triggering state transaction. Delivery is at-least-once; mark sent only after Telegram accepts. Never send agent tool progress.
